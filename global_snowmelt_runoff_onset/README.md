# global_snowmelt_runoff_onset

Core Python package implementing the dataset creation algorithm from manuscript Sect. 2.2. Installed as an editable dependency via pixi (`global-snowmelt-runoff-onset = { path = ".", editable = true }` in `pixi.toml`); imported by the notebooks/scripts in `processing/`, `dataset_utils/`, `dataset_evaluation/`, and `visualize/`, and by the standalone [global_snowmelt_runoff_onset_analysis](https://github.com/egagli/global_snowmelt_runoff_onset_analysis) repo (which editable-installs this package from a sibling clone).

## Modules

| Module | Purpose |
| --- | --- |
| [`config.py`](config.py) | `Config` — loads a versioned `config/global_config_vN.txt` file, builds the global geobox and tile grid (`odc.geo`), defines the chunking/sharding strategy, and connects to Azure Blob Storage. For configs ≥ v10 it opens the Icechunk output repository (`open_output_repo()`, with per-water-year manifest splitting and storage-retry settings); for configs ≤ v9 it keeps the legacy pre-allocated Zarr v2 store plus CSV status tracking (`get_list_of_tiles()`). `Tile` — a single processing unit (bbox, row/col, geobox). Two things a newcomer hits first on load failures: `_validate_grid()` (asserts the config's `expected_grid_shape`/`expected_tile_grid` tripwires) and `_check_sas_token_expiration()`. |
| [`processing.py`](processing.py) | The core algorithm: `search_sentinel1_items()` (retried Planetary Computer STAC search — distinguishes transient MPC failures from genuinely-empty regions) + `load_sentinel1_rtc()` (lazy odc-stac load; the two compose into `get_sentinel1_rtc()`), `get_spatiotemporal_snow_cover_mask()` (MODIS-derived snow phenology masking — reads the `MODIS_snow_phenology` icechunk store for configs ≥ v10, or the legacy `MODIS_seasonal_snow_mask` Zarr v2 store for configs ≤ v9), `apply_all_masks()`, `filter_insufficient_pixels_per_orbit()`, `calculate_runoff_onset()`, and supporting helpers (temporal resolution, DOWY conversion, gap analysis). |
| [`store.py`](store.py) | v10+ output store schema and initialization: the sharded Zarr v3 template (one tile × water year per shard, small inner chunks), metadata-only `initialize_store()`, and `tile_region_slices()` (exact integer region slices per tile). Also `grid_pixel_offset()` / `tile_region_slices_on_grid()` — the v9↔v10 grid-translation helpers (v9 tile (r,c) == v10 tile (r+2,c)) behind `verify_grid_alignment.py`, `migrate_registry_to_extended_grid.py`, and the v9-vs-v10 comparison notebook. |
| [`status.py`](status.py) | Processing status derived from Icechunk commit history: structured commit metadata schema (`build_commit_metadata()`), `get_commit_records()` (raw commit → DataFrame accessor everything else builds on, incl. stats and compute-platform `provenance` columns), `get_tile_status_gdf()` (per-tile × water-year status incl. composite staleness), `get_remaining_work()` (dispatch lists for GitHub Actions / `run_tiles.py`). Also the hemisphere-aware water-year eligibility gate — `season_end()`, `wy_eligible()`, `tile_hemisphere()` — implementing the config's `trailing_buffer_days` in both dispatch and processing (see `processing/README.md`, *Adding new water years*). Replaces the ≤ v9 CSV tracking. |
| [`qc.py`](qc.py) | Sampling-based quality gates on the data the fleet wrote, behind [`processing/3_quality_check_tiles.ipynb`](../processing/3_quality_check_tiles.ipynb) — the counterpart to `status.py`, which gates the ledger rather than the data. `check_schema()` (dtype/fill/scale/shard-geometry/grid lint, metadata only), `check_ledger()` (commit `stats.valid_px` must equal the slab's valid-pixel count; `empty` markers and absent commits must find unwritten slabs), `check_invariants()` (value ranges, `runoff_onset` valid ⇒ `temporal_resolution` valid), `check_composites()` (recompute via `processing.median_*_with_min_obs`, agree within the int16 quantization step — catches stale composites), `check_seams()` (tile-boundary discontinuity ratio), `fingerprint()`/`compare_fingerprints()` (the per-release regression baseline that replaced v9 diffing), `summarize()` (one PASS/FAIL row per gate), and `view_tile()` (composites over a UTM basemap plus per-year onset/anomaly/temporal-resolution facets). `test_tiles()` reads the battery from `processing/tile_data/test_tiles_<version>.txt` so the list lives in exactly one place; `open_release()` pins reads to the config's `release_tag`. |
| [`provenance.py`](provenance.py) | `collect_provenance()` — compute-platform metadata embedded in every commit (GitHub Actions run/runner, JupyterHub/CryoCloud session, or local hostname; package versions; code SHA; machine size `cpu_count`/`memory_gb` for CPU-core-hour accounting). |
| [`results.py`](results.py) | `save_result_table()` — durable homes for manuscript-cited numbers: writes a DataFrame to `results/[<version>/]<name>.csv` with `_version`/`_git_sha`/`_written_at` provenance columns. Convention: every number quoted in the manuscript must exist in a `results/` file — notebook cell outputs and figure annotations are not provenance. Used across `dataset_evaluation/` and `processing/0_select_tiles_to_process.ipynb`. |
| [`plot_utils.py`](plot_utils.py) | Shared plotting helpers **and the repository's figure conventions** — its module docstring is the numbered reference (per-variable colour limits, month colorbars for DOWY, never hardcode a water-year count, projected/UTM-or-equal-area maps, scalebar placement, hillshade zorder, versioned figure dirs, save settings); read it before writing a new figure. Anything expressible as code is a constant or helper here rather than prose: `VARIABLE_KW`/`variable_kw()` (the single source of truth for cmap/vmin/vmax per data variable, with explicit per-call overrides), `HILLSHADE_KW`, `create_month_colorbar()` (DOWY→month labels, both hemispheres), `create_diverging_colorbar()` (auto-shrinks its two end annotations so they can't collide on a narrow axes), `plot_geoms()`, and water-year calendar constants. Plus five small regional-map primitives factored out of `visualize/regions/`: `load_hillshade()` (clip + reproject `visualize/data/global_hillshade_robinson.tif` into a region's CRS), `style_map_axes()` (bare map panel: no ticks/frame/title, equal aspect, optional bounds), `add_context_inset()` (zoomed-out locator inset drawn *inside* a map axes, reusing the same variable/colormap/hillshade and outlining the main extent), `add_scalebar()` (`matplotlib-scalebar` with map-legible defaults; only valid on a metre-based CRS), and `orthographic_locator_map()` (globe-scale locator). Each does one repetitive thing and returns the axes, so a notebook can always drop back to raw matplotlib. |
| `global_snowmelt_runoff_onset.py` | Empty (0 bytes) — stale packaging-scaffold stub. To delete it, also remove `import global_snowmelt_runoff_onset.global_snowmelt_runoff_onset` from [`__init__.py`](__init__.py) line 1, or every package import breaks. |

`analysis.py` (tile-dataset enrichment + parquet export helpers) moved to the `gsro_analysis` package in the [global_snowmelt_runoff_onset_analysis](https://github.com/egagli/global_snowmelt_runoff_onset_analysis) repo in July 2026.
